# T018: the canary pack: every gate proven red, on every gate change (backlog B6)

Repo: `Mivr/c-rigor-gate`. Branch `task/T018`. Read `AGENTS.md`, `plan/backlog.md` (B6), `plan/audits/R001-gate-audit.md`,
`docs/grade.md`, `docs/gate.md`, `gate/order.txt`, `selftest/grade.sh` and `selftest/grade_product/**` (the existing
per-case approach). **In parallel:** T011, T013 (`grade*.py`, `product_layout.py`, `products/**`), T014, T015,
T017. Touch none of their files.

## Why
Self-tests check each component as its author imagined it. A canary pack is the standing, adversarial proof
that the **assembled** gate still says FAIL for every known cheat, so a later gate change can't silently disarm a
check. Every bypass found so far (T001–T005 reviews, R001, A017's BUCK finding) becomes a canary.

## Allowed paths
`canaries/**` (new), `selftest/canaries.sh` (new), `docs/canaries.md` (new), `plan/backlog.md` (mark B6).

## Requirements
1. `canaries/<id>/` each holds a tiny product (git history generated by the script, never committed as a nested
   repo), `product.toml`, `policy.toml`, `expected-tests.json`, a task contract, and `expect.json`. The expect file names the gate
   that must FAIL, the finding rule ids that must appear, and optionally gates that must be NOT_RUN. **A canary
   passes only if the verdict is FAIL with exactly the expected failing gate and rule.** A FAIL for some other
   reason is a canary failure (a broken fixture hides a disarmed check).
2. Cover at least one canary per gate in `gate/order.txt` and per known bypass class:
   - files outside the contract;
   - a NOLINT or pragma suppression;
   - `#line` spoofing;
   - per-file flags in `srcs`;
   - a hidden `.buckconfig`;
   - a cross-cell dep;
   - a raw rule in BUCK;
   - a BUCK assignment or concatenation;
   - a denied libc symbol;
   - a function pointer to a denied symbol;
   - a reserved `mbedtls_` definition;
   - git replace or graft;
   - a test that inherits the results fd;
   - a removed expected test;
   - a skipped test;
   - a heap overflow seen only in san;
   - a weak test with a surviving mutant;
   - an unviable-ratio module;
   - a test peer in a library.

   Where a check is in flight on another branch (structure, builtins, layout coverage, trajectory, generator accounting),
   add the canary with `"pending": "<task id>"`. Pending canaries run and print their verdict but don't fail the
   pack, and the pack prints the list of pending ones.
3. `selftest/canaries.sh` runs them all through `rigor grade` (cached is fine; one `--uncached` canary to prove the
   path), in parallel where the RE farm allows, and prints a table: canary, expected, got, ok. Exit 1 on any
   non-pending miss. A warm re-run must be fast; report the cold and warm times.
4. `docs/canaries.md`: how to add a canary for every new bypass (the rule: no bypass fix merges without its
   canary).

## Acceptance
```sh
selftest/canaries.sh
selftest/gate.sh
```
Report: the canary table, the pending list, the cold and warm times, and any canary that didn't go red for the
expected reason. That last one is a real gate bug: report it, don't fix it here.
