# T1xx.01: UI probe measurements (P004 visual gate), 2026-11-13/14, lane W32

Throwaway probe on business-apps `a318b33` (the historic canary; gate submodule `78d1fc3`) plus a Rust feasibility spike.
Nothing here is gate code. The probe was never committed to business-apps; its source lives outside this repo
(see "Where the probe lives"). Every number below was printed by the probe or by a Buck2 test run; commands are in
"Reproduce".

**Host caveat.** The machine has 2 CPUs and ran at load average 14 to 27 during the runs, so wall time was 1.3 to 1.7 times
CPU time and unusable. All times below are **process CPU time** (`CLOCK_PROCESS_CPUTIME_ID`) of one thread, release `-O2`,
LVGL software renderer, 1280x800 XRGB. They are repeatable (two full runs after the settle fix: sweep totals 60.93 s and 60.92 s; per-stage means
within 2%), but they are for this CPU, not for an RE worker.

### 3.1 What this says about the §4.3 estimate

- Render is **0.49 ms, not 5–15 ms**, because uiloop applies a diff and LVGL repaints only dirty strips. A fresh full frame
  (open, render, close) is 1.9 ms. The CRC over the whole frame (0.76 ms) now costs more than the render.
- Hit injection is **about 0.5 µs per tap, not 0.1 ms**. The cost is the indev path only: `uil_pointer` down/up queue,
  one `uil_step`, intent posted. 5000 of 5000 calibration taps on key "1" queued their intent. The frame was byte-identical
  after every sweep of probes (0 changed frames), so a tap does not repaint.
- Ink attribution is the only stage near the estimate: 1.5 ms per node, two `lv_refr_now` calls each. It is 96% of the
  44.3 ms. All other stages together cost 1.8 ms.
- Sweep: 2061 states x 44.3 ms = **1.5 CPU-min** (design: 2–4 CPU-min for 3k states). Pseudo pass included.

### 3.2 Cheaper ink attribution (not built)

The probe's differential is the naive one. The ink of a node whose subtree and rect are unchanged against an already
inked state is the same, so the sweep can attribute ink once per (scene-structure key) and reuse it, and a single hide of
a whole group plus one repaint attributes its members by rect. This was not tried; it is a design option, not a result.

### 3.3 What was not measured, so BFS cost is still an estimate

The probe drives views, not the reactor. It does not measure `uim_apply`/`uim_advance` path replay (design: µs per step),
nor how many abstract states the sealed catalogue reaches (design: 20k at depth 12). Cost of the BFS tier is therefore
`N_states x per-state cost`, with N unknown:

| N reachable abstract states | render+CRC+dump only (1.75 ms) | full pipeline (44.3 ms) |
|---|---|---|
| 5,000 | 9 s | 3.7 min |
| 20,000 | 35 s | 14.8 min |
| 100,000 | 2.9 min | 1.2 h |

On 64 farm slots the 20k row is under 1 minute of wall for the cheap row and about 15 s of pure compute per shard
for the full row, before action overhead. Replay-from-boot at depth 12 costs 12 reactor steps plus one `uil_open` (1.9 ms).

## 4. Determinism and a trap

### 4.1 The settle rule (finding about the harness, not the product)

LVGL's refresh timer fires every 33 ms of tick time and uiloop is stepped by 16 ms. After a scene change the frame is
**complete only after 3 steps (49 ms virtual time)**. My first settle loop stopped as soon as one step flushed nothing
and then reported that **all 1374 frames depended on the previous state** (forward vs reverse order differed for every
state; a forced `uil_redraw` fixed them; the O3 dump was identical). The cause was my loop, not uiloop: the splash frame
was captured while the Welcome frame was still on screen. The rule that gives identical frames is "at least 3 steps, then
until two consecutive steps flush no strip" (mean exactly 3 steps for every state). P004 §4.2's "step by frame and stop
at every deadline" is right; a gate that captures after one step will produce one-frame-lagging goldens that look like
flake. A check that the capture is at a quiet frame (two identical consecutive frames) belongs in the probe protocol.

### 4.2 Results (after the fix)

### 5.1 O3 against O4 agreement

For 13,662 labels with ink, the computed per-glyph box union (`lv_label_get_letter_pos` + glyph descriptors) matches the
measured ink bounding box within 2 px on all four sides; 1,528 labels have glyph boxes outside their own object
(clipped text). The per-glyph box is therefore a usable O3 fact and the clipped cases are exactly the F6/F8 class.

### 5.2 Pseudo-locale (§11 Q14)

A pseudo catalogue (EN accented, +40% length, brackets, `{n}` kept) replaced the `bg` slot via a one-line hook in
`uiloop.c` (scratch only). All 687 `bg` views rendered, 44.2 ms per state, 0 of 687 differ on a second pass.
Findings count over the same 687 views: glyph-clipped text **pseudo 461, bg 465, en 358**; text-truncated **pseudo 200,
bg 198, en 2**. Pseudo adds little over real Bulgarian because the layout already cuts text at one line and `bg` is
already 40% longer than `en` in the catalogue. As a catch for rows that fit in bg and not in a longer language it is
only as good as the margin; at merge it costs +50% sweep time (30 s of 91 s CPU).

| Spike: 200 x (`ViewState::at(Idle{entered})`, language alternating, `lockers_bind::render`, read the full element tree) inside that test | **p50 3.69 ms, p95 4.00 ms, max 4.15 ms per state**, 60 nodes; tree lines carry label, value, x, y, w, h, role (patch: `/var/tmp/cache/W32/probe-src/rust-spike-e2e-lib.patch`, scratch clone only) |

What exists: ViewState production with fake ports and an injected clock; a headless Slint tree with the same fields as the
oracle bundle. What does not: the driver binary, the sealed-catalogue event mapping, a protocol, timer stepping
(`i_slint_backend_testing` mock time is once per process, so the driver must be one long-lived process that replays a
path by building a fresh `KioskViewModel` against the same window), and parity on the 23 scenarios. A spike line that
matters for BFS: the tree costs 3.7 ms per **new** abstract state; per event only the `ViewState` comparison is needed.

**Go/no-go: go** for T1xx.20 on the ViewState + Slint-tree level. It is not "free": it needs a club-apps contributor lane
and the club fork binary on whatever machine runs the farm job. The spike does not show that every catalogue event
maps to an existing viewmodel call (`digit`, `backspace`, `submit`, `scanned`, `tick`, `choose_size`, `dismiss` exist;
probe taps and virtual-time events have no Rust counterpart, they would be mapped to those calls).

## 10. Answers to carry into P004

1. §4.3 per-state cost: replace "40–80 ms" with the stage table in section 3; the model should treat ink attribution as
   the budget item (about 43 ms) and everything else as 1.8 ms.
2. Full BFS at merge is affordable if the BFS tier does render + CRC + dump per state and ink once per structure class;
   the number to measure next is the reachable abstract-state count and path replay cost, which needs the reactor (T1xx.0x
   `c_ui_model`), not this probe.
3. Add to the probe protocol: capture only at a quiet frame (3 steps minimum, then two identical frames).
4. Rust lockstep: go (T1xx.20), at ViewState + element-tree granularity; one long-lived driver process.
5. Owner input still needed: panel size and viewing distance (§11 Q9).
