**What the literature adds.** The pattern is the one the GUI-oracle literature describes: the oracle, not input
generation, is the weak point of GUI testing, and checks that compare only one widget or only the end state miss
faults that are visible in a short "window of opportunity" [E: Memon 2003; Xie 2007; Banerjee 2013; Kong 2019]. All 11
failures are in states the existing tests could already reach; what was missing were generic checks over (time, event,
scene) traces and over rendered geometry [E: synthesis verdict 1, built on Harrison 2019; Konrad 2005; Ryou 2018] [I].

## 2. Principles

1. **Observe what the visitor observes, at every stage.** A check that reads the model can only find model bugs. Read
   the four stages of §2.1 and compare adjacent stages; use the scene as the *intent* and the LVGL tree and pixels as
   what was *done* (stage conformance is itself a layer, L3) [E: Song 2022] [I].
2. **Invariants over examples.** A check is a property of *every* state the app can show, not an assertion about one
   screenshot. Then exploration, not scenario writing, decides coverage.
3. **Diverse methods** (P003 P5): every failure class is caught at two layers that share no code path (e.g. F3:
   scene geometry *and* hit-test injection through LVGL *and* oracle relations). Reference-differential checks inherit
   the reference's bugs, so every class also has a Rust-independent invariant (L4) [E: McKeeman 1998; Barr 2015].
4. **Determinism by construction.** Virtual clock, fixed seeds, headless software rendering, settle-by-equality; every
   trace runs twice and must be byte-identical (L0); no retries — irreproducibility is itself a failure. A check that
   can flake is a check that will be waived [E: Romano 2021; Parry 2021; Thorve 2018].
5. **The oracle tells *what*, the contract tells *how much*.** Labels and relations come from the Rust bundle and the
   lockstep driver; tolerances and timers are owner-sealed numbers with provenance, never inferred from the C side.
6. **A pinned deviation is debt, not a decision.** Writing "Pinned: omitted" in a header does not make a defect go away.
7. **Pixels last, tolerance 0.** Structure and relations first; exact C-vs-C pixels only as the final catch-all for
   "scene correct but never painted"; no perceptual similarity metric is ever a verdict [E: Alégroth 2018; Ding 2020;
   LVGL 2026 (prac)].
8. **Seal what excuses.** Anything that can turn a red check green without changing the product (golden, allowlist,
   no-op list, threshold, abstraction key, event catalogue) is owner-sealed and never changes in the same change as the
   code it excuses [E: Fujita 2023] [I].
9. **A learned model may explain, never decide** (L7) [E: Kaynak 2025; Hu 2025].

### 2.1 Four observation stages [I, built on E: Song 2022]

| Stage | What is recorded per step | Produced by | Trusted because |
|---|---|---|---|
| **O1 view state** | Projection of `lk_view_t` (the abstraction-key fields of §4.3 plus every field a property reads) | product model adapter (`uim_semantic`, `uim_trace`) | pure reactor; checked by L0 and by Rust lockstep (L1) |
| **O2 scene graph** | Per node: key, role, rect, z/layer, style id, msgid + args, intent:arg, flags (enabled, inert), **declared input policy** (§3.1 `overlay-policy`), **declared importance level**, wrap/ellipsis policy; plus every **scene patch** emitted per reactor instant (not only the scene at render time) | product scene builders, read through the adapter | it is the *intent*; it is compared with O3 (L3) |
| **O3 LVGL object tree** (post-lvrender, post-layout) | Per object: class, absolute coords, parent, hidden, clickable, label text, resolved font id and line height, text align, long mode, laid-out line count, per-glyph ink boxes, bg colour/opa, scroll/clip ancestors; the **hit-test table** from the production `lv_indev` path; LVGL object create/delete events between frames | `gate//ui:lvprobe` (gate code over gate-owned LVGL) | gate code reads it; the product cannot report it |
| **O4 framebuffer** | Full-frame CRC, per-object region hashes, per-node ink box and ink count (hide/re-render differential), luminance under glyphs and indicators for contrast | `gate//ui:lvprobe` on the capturing flush | same buffer the shell blits (§11 Q1) |

The **gate's a11y projection is computed from O3**, by gate code, so it is an independent observation of what was
drawn, not a re-encoding of the scene [I]. Comparing it with the O2 projection is an L3 check
(`ui-render.a11y-stage-mismatch`). This settles the gate side of the draft's open question Q2; whether the
*product's* e2e `tree` command (used by the club driver) also becomes LVGL-derived stays an owner decision (§11 Q2,
recommended yes).

The trace record per explored step is therefore
`(t_virtual, event, O1, O2 + patches, O3, a11y(O3), hit(p) for probe points, O4 hashes, oracle projection)`
[E: synthesis §1; I].

## 3. Detector catalogue

Finding ids are `<gate>.<check>`; a finding instance id is `sha256(check, element identity, state class)[:12]`
(element identity = role + owner key range + msgid name; state class = screen, notice kind/phrase, banner set,
language), independent of exploration order. Severity: **E** error, **I** info. Column **L** = oracle layer (§3.0).

### 3.0 The layered oracle stack [E: synthesis §5; I]

All layers are deterministic. A failure at any of L0–L6 blocks; L7 never does. Layers are ordered by cost and by how
early they localise a defect, not by authority: L4 and L5 are as binding as L1.

| Layer | What it checks | Detectors (§3.1–§3.9) | Evidence for the layer |
|---|---|---|---|
| **L0 Determinism** | Every trace run twice under the virtual clock: O1, O2, O3 and O4 byte-identical; fresh render = diff render; no retries; starvation (0-delay rescheduling) fails instead of force-advancing | `ui-explore.model-nondeterministic`, `ui-explore.run-twice-mismatch`, `ui-explore.timer-starvation`, `ui-render.diff-render-divergence` | [E: Su 2021 Genie (replay-twice filter); Parry 2021; Thorve 2018; Chromium 2026 (prac)] |
| **L1 Rust structural parity** | Per event **and** per timer deadline, lockstep: screen inventory, node set by semantic key, msgid + formatted args, dialog stack, node lifetimes; content recall 1.0 | `ui-parity.oracle-label-missing`, `oracle-content-recall`, `oracle-label-extra` (I), `oracle-scenario-diverged`, `oracle-lockstep-diverged`, `oracle-lifetime-diverged`, `oracle-screen-unreached`, `pinned-deviation` (debt) | [E: Memon 2003; Xie 2007; Fazzini 2017; Rushby 2002] |
| **L2 Per-node property parity** | Per matched node: role, emphasis/size class, alignment class, selected, visible/hittable, relative geometry (±1 px relations), node count of a value | `ui-parity.oracle-layout-relation`, `oracle-size-class`, `oracle-node-property`; `ui-scene.value-split` | [E: Roy Choudhary 2013; Walsh 2017; Fazzini 2017; Bielik 2018] |
| **L3 Stage conformance** | Scene → LVGL: rect, text, resolved font, alignment, flags, long mode match the scene and the sealed style table; a11y(O3) = scene projection | `ui-render.render-geometry-mismatch`, `render-text-mismatch`, `font-size-mismatch`, `align-mismatch`, `flag-mismatch`, `a11y-stage-mismatch`; `ui-fit.font-shrunk` | [E: Song 2022] [I for the LVGL level] |
| **L4 Rust-independent invariants** | Temporal/HMI templates (dwell, flicker, feedback, mode visibility, no invisible transition, countdown cadence); hit-test reachability, overlay input policy, target size and spacing, dead intents, echo correspondence; text fit and full string shown; legibility in visual angle; contrast; required content | most of `ui-scene`, `ui-fit`, `ui-input`, `ui-time`; `ui-render.invisible-node`, `covered-node`, `contrast-low`, `glyph-run-gap` | [E: Harrison 2019; Konrad 2005; Bolton 2013; Degani 2002; Ryou 2018; Mesbah 2012; Alshayban 2022; Legge 2011] |
| **L5 Exact metamorphic relations** | EN/BG/pseudo-locale renders; language changes exactly the msgid nodes whose strings differ; round-trips (EN→BG→EN, digit+backspace, open/close by every terminator); sibling uniformity; clock-origin invariance; 2× text (nightly) | `ui-meta.*` (§3.8); `ui-time.clock-origin-divergence` | [E: Sun 2021; Su 2022; Alameer 2016; Alshayban 2022; Harrison 2019] |
| **L6 Exact golden frames** | Per-object region hashes + full frame, tolerance 0, on the pinned software renderer; generated by the gate only from a state that passed L0–L5 | `ui-golden.frame-mismatch` (§3.9) | [E: LVGL 2026 (prac); Bürkle 2024; Alégroth 2018; Fujita 2023] |
| **L7 Explanation** | An LLM/VLM may attach a prose explanation to a deterministic finding; it is never read by the verdict | `explanation` field of a finding (§4.5) | [E: Kaynak 2025; Hu 2025] |

Learned screenshot detectors (CNN, VLM) are excluded from L0–L6: they plateau around P/R 0.8 at 10–20% FPR, and a
high-recall frontier VLM reached FPR 0.83 [E: Liu 2020; Liu 2022; Wang 2019; Hu 2025].

### 3.1 Scene level (pure; per explored state; no rasterisation) — gate `ui-scene`

| Check | L | Rule (deterministic) | Catches |
|---|---|---|---|
| `occluded-target` E | L4 | An interactive node (intent ≠ 0, not inert, not behind a declared modal blocker) any of whose probe points P(n) (§3.10) lies under a later-painted, non-inert node that is not its ancestor or descendant | F3a |

### 3.2 Text fit — gate `ui-fit` (P003's name, made concrete)

### 3.5 Temporal (event → view → scene trace on a virtual clock) — gate `ui-time`

The trace is the sequence `(t, input, emitted events, scene patches, scene hash, semantic tree)` the explorer records
for every path (§4). **Patches, not snapshots:** a node created and destroyed within one reactor instant or one handler
pass is invisible to per-deadline snapshots, so the trace logs every scene patch and every LVGL create/delete event
[I; E: Xie 2007 (window of opportunity)]. Timers come from the contract, which copies ui-rules.md:33-46 (choose 30 s,
opened 8 s, dialogs 8 s, report 5 min, lockout 60 s, snackbar 4 s). All properties are **bounded** (safety) forms,
stored as named instances of real-time specification patterns; the spec linter rejects unbounded liveness, because
43 of 97 standard pattern formulas yield monitors that never conclude on finite traces [E: Bauer 2011; Konrad 2005;
Dwyer 1999; Ho 2014].

|---|---|---|---|

### 3.8 Metamorphic relations (L5) — gate `ui-meta` (new)

Metamorphic oracles are precise only when the relation is exact: round-trip identity 83.2% and pairing across scales
97%, against 19–41% for heuristic relations [E: Sun 2021; Su 2022; Su 2021 Genie; Wang 2022]. A pure reactor, a
virtual clock and msgids make every relation below exact [I].

| Check | L | Rule | Catches |
|---|---|---|---|

**Pseudo-locale** [P]: per msgid, a string of length max(BG length, IBM-table expansion of the EN length — 2–3× for

used because short labels expand far more than sentences [E: Practitioner 2022 (prac)]. No precision/recall exists for
pseudolocalisation and no Bulgarian expansion data exist [E: none found — gap G3].

### 4.2 The probe protocol (gate header `gate//ui:model.h`, sketch [P])

```c
/* Product implements; static storage; pure apart from the virtual clock it is given. */
bool     uim_open(uim_t *m, uint64_t clock_origin_ms, uint64_t seed);          /* boot to first stable scene   */
uint16_t uim_env_inputs(uim_t *m, uim_input_t *out, uint16_t cap);            /* enabled env/fault inputs now  */
bool     uim_apply(uim_t *m, const uim_input_t *in);                           /* env input, wedge line, intent */
uint64_t uim_next_due(const uim_t *m);                                         /* next timer, or UINT64_MAX    */
bool     uim_advance(uim_t *m, uint64_t to_ms);                                /* step frames up to `to`       */
bool     uim_frame(uim_t *m, lv_display_t **disp);                             /* scene adopted + LVGL drawn   */
bool     uim_semantic(uim_t *m, core_buf_t *out);                              /* O1 projection + scene a11y+  */
bool     uim_patches(uim_t *m, core_buf_t *out);                               /* every scene patch since last */

```

`a11y+` = the CLUB_A11Y seven fields plus `key, role, intent:arg, flags, style, importance, input_policy, wrap_policy`
(appended fields; existing drivers read seven). `gate//ui:lvprobe` emits, per state: the O3 tree (class, coords,
hidden, clickable, label text, resolved font id and line height, text align, long mode, laid-out line count, per-glyph
ink boxes, bg colour/opa, clip ancestors), per-node ink box and ink count, the hit-test table for every probe point
(node → intent queued by a press+release through the indev), per-object region hashes, glyph/indicator luminance, the
frame CRC, and the LVGL create/delete events since the previous frame. All C, all bounded, static memory.

**Time stepping** [E: LVGL 2026 (prac)] [I]: `uim_advance` steps the LVGL tick in frame increments (16 ms) and runs
`lv_timer_handler` at every step, and always stops exactly at every reactor deadline; it never uses
`lv_test_fast_forward`-style single jumps, which run only one timer pass and can hide intermediate firings. The initial
virtual epoch is pinned (as club-apps already does, §5).

Exploration needs no product snapshot API: paths are replayed from `uim_open` (depth ≤ 12, reactor steps are µs).
A memcpy snapshot of the static model is an optional speed-up (a C strength, P003 §3).

### 4.3 Strategies, bounds and coverage

1. **Domain sweep** (needs only the pure builders): enumerate equivalence classes of `lk_view_t`, build the scene
   (`lkui_build` + `lkui_notices`), render, run §3.1–3.4 and §3.8. Classes [P]:

| Factor | Classes | Count |
|---|---|---|
| Screen variants | SPLASH 1; WELCOME pad_len {0,1,6,25,26,64} 6; CHOOSE n_sizes 1..6 × {all free, all full, alternating} × countdown {max, 1 s} 36; OPENED digits {1,2,3} × first_time × countdown 12; SHIFT {0/0, 1/2, 2/2, max} 4; REPORT {0, 65535, **all sections populated**} × write_failed × countdown 12; LOCKOUT 2; FAULT 2 screens × 10 faults 20 | 93 |
| Language | bg, en, **pseudo** | ×3 |
| Notice (over WELCOME/OPENED where the view allows) | none; dialogs: 3 rejects, no-locker, fault 10 × 3 doors × {0, 1-digit, 3-digit locker} = 94; snackbar 1; banner-kind notice × 13 phrases | 109 |
| Banners | single variants: not_saved, audit, sync {rejected 3 status classes, late}, codes offline, codes stale, self-test {OK, 9 issue bits, 3 count bits} ≈ 21; subsets of the 6 kinds 64 | |

   The "all sections populated" REPORT fixture (every counter non-zero, rejected codes, lockouts, relay-down and
   app-start lines present) exists because sections that appear only with specific data are a known blind spot
   [E: Su 2021 Themis] [I]. Coverage set [P]: (a) every screen variant × language with no message (279); (b) every
   notice variant × host screen × language (≈ 654); (c) every single banner variant × screens where shown × language
   (≈ 567); (d) all 64 banner subsets × {WELCOME, OPENED, CHOOSE} × language (576); (e) a strength-2 covering array over
   (screen variant, notice, banner subset, language) ≈ a few hundred — kept as a cheap supplement only; no corpus
   source evaluates covering arrays for GUI state selection [E: none found — gap, §15 LIT-1]. **Total ≈ 2.4k–3k
   states.**

2. **Event catalogue** (owner-sealed, versioned, `products/business-apps/ui/lockers.events.toml`) [E: Belli 2001;
   Memon 2001; synthesis §4] [I]:
   - **U1 intent taps**: a centre tap on every interactive node **of the rendered O3 tree** (never a product list).
   - **U2 probe taps through the production LVGL hit-test**: P(n) for every interactive node (§3.10), plus a coarse
     8×6 whole-screen grid; the expected outcome of each probe is computed from the scene (topmost enabled,
     non-inert intent node at p, or "nothing") [E: Holz 2010; Henze 2011; Belli 2001].
   - **U3 complement taps that must do nothing**: non-interactive points, points under a declared modal scrim, disabled
     keys; expected outcome: no intent, or the declared dismiss [E: Belli 2001].
   - **U4 code macros with boundary classes**: empty, 1 digit, max − 1, max, max + 1 (64/65), valid visitor, valid
     staff, unknown, expired, non-digit — via the wedge and via the pad; per-digit events only from boundary states,
     so the per-key echo of F2 is still checked [E: Su 2021 Themis (deep paths exceed budgets)] [I].
   - **U5 language** as an ordinary event (both toggles in every state that shows them); explorers have a known blind
     spot for language changes [E: Su 2021 Themis].
   - **E1 environment replies**: the product's env/fault inputs (relay down/up/stuck, open fault per kind, book save
     fail, audit fail, disk full, codes offline/stale/failed, sync rejected/late, self-test results), each with reply
     classes ok / reject(reason) / timeout / error where the product has them.
   - **T1 virtual-time events**: `fire_next_deadline`, `advance(1 frame)`, `advance(deadline − 1 frame)`, `+tick`,
     `+5 min idle` — so minimum-dwell and bounded-response properties are checkable without real-time waits
     [E: O'Connor 2022 (real waiting made faults rare and slow)].

3. **Abstraction key (dedup)** — an **owner-declared projection of O1**, hashed exactly; never learned and never a
   similarity threshold (a universal similarity threshold reached crawl F1 0.24) [E: Yandrapally 2020; Baek 2016].
   Fields [P]: screen, notice/dialog stack (kind + phrase), banner set, language, every toggle group's selection,
   pad length class {0, 1, max − 1, max}, staff mode, report data class, presence of each pending timer bucketed
   {none, pending, < 1 frame}, countdown bucket {running, zero}. **Rule: every variable read by any property or
   oracle projection is in the key**, otherwise a property is checked in only one representative of a merged class
   (dropping text-box contents, as one explorer does, would hide F2) [E: Dong 2020; Amalfitano 2015]. The full O1–O4
   observation is kept for every visited step; the key decides only whether to expand a state again [E: Mesbah 2012
   Crawljax]. The key is **validated by seeded mutants**: for each field excluded from the key, a nightly mutant whose
   bug depends only on that field must be killed (C12) [I]; and `key-too-coarse` (§3.7) flags equal keys with
   different normalised trees [I].

4. **Reachability BFS** from boot over (abstract state × catalogue event), depth bound D = 12 macro-level events, 20k
   states [P]; report new abstract states per depth (`depth-unsaturated`). BFS gives shortest counterexamples, and its
   spanning tree is a compact regression corpus [E: Choi 2017 (16.9× smaller suites keeping every exception)]. The
   **Rust oracle runs in lockstep** on the same event path (L1/L2 per event and per deadline) [E: Rushby 2002;
   Xie 2007] [P]. Exhaustive search of an exact model is cheap here; on real GUIs event-pair coverage cost
   309–1,204 machine-hours [E: Nguyen 2014]. No paper evaluates exhaustive exploration of Elm/Redux-style reducers;
   the argument is by analogy to explicit-state HMI checking [E: none found — gap G1].

5. **Seeded random walks** (long paths, 200 seeds at merge — the same seeds P003 §7.4 uses for `sim`; swarm-style
   per-run event subsets nightly), each also run at 4 extra clock origins for `clock-origin-divergence`. Random is the
   supplement, not the primary, on a pure reactor [E: Groce 2012 (+42% distinct crash causes); Choudhary 2015] [I].

6. **Oracle scenario replay** (§4.4).

**Coverage criteria** (findings `ui-coverage-gap`): C1 every screen class × language rendered — **required**; C2 every
catalogue message × language rendered in each host role it can take (screen text, notice title/body/detail, banner) —
**required** (ties to P003 `ui-fit` exhaustiveness); C3 every interactive node class tapped in every screen class —
**required**; C4 every notice kind over every host screen, banner counts {0,1,2,6} — required; C5 every contract timer
observed to expiry at ≥ 2 clock origins — **required**; C6 every env fault injected in every screen class where it is
enabled (pairwise) — reported; C7 every oracle scenario step replayed — **required**; **C8 100% of reachable (abstract
state, catalogue event) pairs, probe and complement taps included — required** [E: Memon 2001 (event-pair);
Prowell 1999 (arc coverage)]; **C9 every dialog × every close path** (timeout, button, tap-outside, superseding notice)
— **required** [E: Memon 2001 (invocation-termination)]; **C10 every Rust screen reached in C — required**; **C11 event
triples ending in a time or dialog event — nightly, reported** (each +10 points of triple coverage multiplied the odds
of detecting a fault by 2.14 in one small subject) [E: Strecker 2008]; **C12 every abstraction-key validation mutant
killed — nightly, required** [I].

**Runtime estimate** [P, to be measured by T1xx.01]: reactor + scene build per state: µs. Full-frame LVGL software
render at 1280x800 XRGB8888: assumed 5–15 ms. Ink attribution (hide one object, re-render only its area) ≈ 0.5–2 ms per
painted node × ~25 nodes. Hit injection: ~0.1 ms per probe point × ~20 points × ~15 interactive nodes. ⇒ ≈ 40–80 ms per
rendered state. The synthesis estimate is the same order: 10⁴–10⁶ reactor transitions at 0.1–1 ms, rendering only once
per new abstract state × locale, 1–10 core-minutes [I]. Sweep (3k states): 2–4 CPU-min; BFS (20k): 15–30 CPU-min; walks
(200 × ~200 steps, render only on scene change): a few CPU-min. Sharded over the farm (concurrency 64), the merge tier
should fit in a few minutes wall; the synthesis budget is < 10 min [P].

### 4.4 Headless scenario replay

The 23 scenario files (`club-apps:tools/e2e/scenarios/*.txt`, mirrored in the harness) use a closed command set
(`wait/click/type/key/absent/pause/within/label-has/expect-value/freeze-clock/thaw-clock/screenshot`, README). The
explorer interprets them against the probe: `click L` = centre tap on the **render-tree** node labelled L (button
first, as the Rust driver does), `type`/`key enter` = wedge, `pause`/`within` = virtual time, `freeze-clock` = stop
advancing, `screenshot N` = capture render tree + frame after the scene settles (two identical semantic trees, as the
Rust driver does). Output per step: `C/<scenario>/<step>.{rtree,png}` with the same names as the oracle bundle.

## 5. The oracle side, reproducible

- **Bundle content**: per scenario step that has a `screenshot`: the Rust tree (`.tree.txt`, real Slint element
  geometry), the PNG, and a manifest (club-apps commit, driver commit, Xvfb geometry, `SLINT_SCALE_FACTOR=1`,
  font hashes). Bound into the verdict by sha256, like the witness and P003's trace bundle.
- **Lockstep driver** [P]: a headless `rust_ui_oracle` that takes the sealed event catalogue (U1–U5, E1, T1) and emits
  the normalised projection of §3.6 per event and per deadline (T1xx.20). It makes L1/L2 cover every explored state,
  not only scenario steps. Feasibility unmeasured (§11 Q13).
- **Determinism already present** in club-apps (`tools/e2e/README.md`): fixed version stamp `Lockers
  0.0.0+e2e2e2e2e2e2`, virtual clock `1796126415000 + BOOT_IDX × 600000`, `freeze-clock` before countdown screens,
  screenshot after two identical trees. Missing: the driver writes no tree file at `screenshot` — one small club-apps
  task (T1xx.11). Acceptance for the bundle producer: two runs on the same commit give `screens-compare … 0 differ`
  **and** byte-identical tree files.
- **Freshness**: D12 freezes Rust lockers behaviour between M5 and M6; the bundle is rebuilt only by a club-apps task
  and a gate change (graded under the previous gate, P003 §10.3).
- **Visibility** [P]: the PNGs and labels are the specification of the look, so implementers may see them (unlike
  P003's trace bundle). The tolerances, normalisation table and the domain/BFS states are gate-side; the domain sweep
  covers states no scenario reaches, so hard-coding the bundle's labels does not pass (and is AGENTS rule 3 anyway).
- **Intentional divergence** is handled in this order [E: Fazzini 2017; McKeeman 1998; Mesbah 2012] [I]:
  (1) normalise substrate differences (relations and ratios, not pixels or fonts); (2) exclude by construction nodes
  without a msgid or marked dynamic; (3) a divergence allowlist under the rules of §8.3; (4) **when Rust is wrong, fix
  Rust** (or a temporary entry linked to a club-apps issue), so the oracle improves instead of being silently forked.
- **Limits**: the oracle reproduces Rust's own bugs (P003 §16; differential testing mostly found bugs in the
  comparison programs [E: McKeeman 1998]), so every L1/L2 check has an L4 counterpart; the Rust tree carries only
  elements with an accessible role, so relations are judged on those.

### 6.3 Gaming resistance

- The checks read the LVGL tree and framebuffer through gate code; the product cannot report geometry or text.
- Taps are injected at render-tree probe points through the shell's own pointer path, not at declared positions.
- Exploration inputs come from the render tree and sealed catalogues; the product's env catalogue is checked for
  completeness; clock origins and seeds are derived from the verdict's input hash, so a special case for a known seed
  or origin fails on the next grade.
- `gate//ui:model.h` symbols may be linked only by `c_ui_probe` targets (symbols policy); product code that detects the
  probe, `CLUB_E2E` or the explorer is AGENTS rule 3 and a symbol violation.
- Scene-vs-render consistency checks (L3) make "fix the a11y tree, not the screen" impossible.
- **No retries**: retry-on-fail converts intermittent defects into passes; with L0 in place irreproducibility is a
  failure [E: Alégroth 2015] [I].
- **Sealing and the same-change rule** (§8.5): goldens, allowlists, no-op lists, thresholds, the abstraction key and
  the event catalogue never change in the same change as the code they excuse; deletions, skips, tolerance raises and
  allowlist additions are counted against a budget [E: Fujita 2023; Thorve 2018].
- **Gate self-mutation** nightly: seeded reactor, scene and lvrender mutants that each property must kill, so vacuous
  properties written by the same agent as the code are found [E: Xiong 2024 (oracle quality depends on property
  quality)] [I].
- **Canaries** (P003: every new gate ships with one): a selftest app with one seeded defect per check, and the
  **historic canary**: business-apps `a318b33` must keep producing findings for all eleven classes F1–F11 (mapping in §7).
  A gate change that loses one fails under the previous-gate rule.
- **LLM output never approves** (L7).

### 6.4 False positives

- **Report first.** A new check runs ○ for [P] 5 nightlies on `main`; its findings are triaged by the refuter role
  (P003 §10.2) and only then promoted to ● by a gate task (the P003 §13 ordering rule, applied per check).
- **Baseline ratchet.** On promotion, the open findings on `main` become a baseline list (ids). The list may only
  shrink (P003 ratchet); a new id fails the merge.
- **No free waiver.** A finding that is not a defect is a P003 §10.2 **claim** ("this is intended") signed by the
  arbiter, bound to the finding id, under a debt cap, ledgered, and refutable by executable evidence (an oracle step
  showing the difference, a tap that misroutes, a rendered crop). An owner decision that departs from the oracle (D14:
  no attribution) is a **normalisation entry** in the sealed contract, not a waiver.
- **Known FP sources and their structural fix** [E as cited] [I]: undeclared floating layers (rule-based overlap checks
  scored P 0.32 / R 0.36 largely because of them [E: Liu 2022]) → declared input policy per layer; intended clips,
  ellipses and overlaps (non-observable overlaps outnumbered true collisions 24 to 8 in one checker [E: Walsh 2017]) →
  declared wrap/ellipsis/clip policy; legitimately superseded messages → declared successor/precedence rules;
  legitimately idempotent taps → sealed no-op list with required feedback; untranslated content in the language
  relation → msgid-level comparison [E: Sun 2021].
- **Tolerances are numbers with provenance** (e.g. `notice-lifetime-short` slack = one tick, from `runtime.h` C2;
  size band [0.8, 1.25] [P] from the measured C/Rust spread at the first PASS, ratcheting inward only). Pixel
  tolerance is 0 and is not a promotion parameter.

### 8.3 Pinned deviations and the divergence allowlist as debt

Every header disagreement line gets a machine-readable tag, e.g. `@deviation(LKUI-L2, oracle="version-line",
state="splash,report", reason="intentional|substrate|reference-bug", link="…", until="T1xx")`. The gate (a facts scan
over headers) lists the tags; `ui-parity` marks each tag whose subject diverges from the bundle as `pinned-deviation`.
The count is a ratchet (P003 §10.1) and has a cap [P] (e.g. 5 per app); a new tag above the cap fails. A tag whose
subject no longer diverges is `deviation-stale` (info → delete the tag). Untagged divergence is still caught by the
other parity checks; tagging only makes it explicit.

The **normalisation table and divergence allowlist** follow the same rules [E: synthesis §5; Fazzini 2017;
McKeeman 1998] [I]: each entry has a key (screen, node semantic key, field), a reason class (substrate / intentional
product difference / reference bug), a link and an expiry; an entry is **never** added in a change that touches the C UI
code it excuses; entries count against a ratcheting budget; a reference-bug entry must link a club-apps issue and
expires when the Rust fix lands. Over-normalisation is itself a blind spot, so the budget is small [I].

### 8.4 Golden frames (precondition for P003 §7.6)

P003 §16 notes that nothing says the first golden is right. P004 narrows that: a golden frame exists only for a state
whose `ui-scene`, `ui-fit`, `ui-render`, `ui-input`, `ui-time`, `ui-meta` and `ui-parity` findings are all clear
(L0–L5), and it is **generated by the gate** from that state, never hand-made or re-recorded by an implementing agent.
Comparison is exact (tolerance 0; per-object region hashes + full frame), built with
`LV_TEST_SCREENSHOT_CREATE_REFERENCE_IMAGE 0` so a missing golden fails; there is no record, update or
verify-and-record mode in CI; a golden is never changed in the same change as UI code; a golden deletion counts
against the budget (§8.5). The first golden is then at least *legible, reachable, tappable, timely and
oracle-consistent*. It does not make it beautiful. [E: LVGL 2026 (prac); Android 2026 (prac); Fujita 2023;
Alégroth 2018]

### 8.5 Sealed artefacts, the same-change rule and the budget [E: Fujita 2023; Thorve 2018; Bauer 2011] [I]

- **Sealed** (owner signature required, held in the gate repo): UI contract incl. thresholds, timers, input policies,
  importance levels; event catalogue; abstraction key; property instances (named Dwyer/Konrad pattern instances); no-op
  list; normalisation table and divergence allowlist; golden set; tolerances.
- **Same-change rule**: a change that modifies a sealed artefact may not modify product UI code (business-apps
  `apps/lockers/{lkui,lkapp,lkrx}`, `lib/ui/**`) and vice versa; the gate checks the diff.
- **Budget**: golden deletions, test/check skips, tolerance raises, allowlist and no-op additions are counted per window
  [P] and above the budget fail; every count is ledgered.
- **Spec linter**: property instances must be bounded (no unbounded `F`/`G`), must name their pattern, and must each
  have a seeded mutant they kill.
- **Gate self-mutation** (nightly): for each property, a seeded reactor/scene/lvrender mutant it must kill; a property
  that kills nothing is reported as vacuous and demoted.

## 10. What this does not do (known limits)

- **No aesthetics.** Colour harmony, spacing rhythm and "looks right" are not decided; parity relations, size
  classes, legibility floors and declared importance are a proxy, as good as the oracle and the contract (§16).
- **The oracle's bugs are reproduced** (P003 §16) by L1/L2; L4 invariants catch the encoded classes only.
- **Domain classes and the abstraction key are chosen by someone.** A missing class or key field is a missing check;
  C1–C12, the key-validation mutants and the BFS limit the damage.
- **BFS dedup by a declared projection** can merge states that differ in hidden state; seeded long walks, the
  clock-origin runs and `key-too-coarse` are the mitigation, not a proof.
- **Headless ≠ the window.** X11 glue (shell_linux, L1, untested by design) is only seen by the nightly Xvfb replay;
  real input-to-photon latency only by the hardware tier.
- **Fonts and LVGL are pinned**; a toolchain bump that changes metrics moves fit results and goldens, by design (it is a
  gate change).
- §16 lists what the literature says stays hard to catch mechanically.

## 11. Open questions (owner decisions)

The draft's eight questions are kept (1–8, updated where the literature changes the default); 9–17 are new.

1. **Golden frames headless or Xvfb?** P003 §7.6 says "under Xvfb"; the headless capturing flush is the same buffer the
   shell blits. Proposal: headless goldens, with T1xx.15 proving equality once. (P003 owner.)
2. **Should the product's C e2e tree become LVGL-derived** (`lkapp/e2e`), so the club driver also sees the screen? The
   gate's own a11y projection is LVGL-derived regardless (D11). Recommendation: yes — make `tree` LVGL-derived and keep
   the scene tree as `stree`; it changes what the existing harness asserts (e.g. `30 s` → `0:30` until F6 is fixed).
   (Owner.)
3. **Pad digits (F2): parity or privacy?** vstate D1 keeps the digits out of traces; Rust shows them. Options: a
   UI-thread-only echo that never enters the trace (uiloop already holds the wedge buffer), or keep dots, make them
   visible, and record a normalisation entry. `echo-correspondence` works either way (it counts glyphs, masked or
   clear). (Owner.)
4. **Oracle bundle visibility** to implementers (§5): visible PNG/labels proposed, unlike P003's trace bundle.
5. **Remaining [P] numbers** — size band [0.8, 1.25], flash window T_perc, covered-ink share, hierarchy ratio k,
   glyph-run gap — who signs the first values: the §6.4 rule (measured at first PASS, ratchet inward) or an owner
   number? (Pixel tolerance is no longer open: it is 0.)
6. **Real-window driver**: reuse the pinned club-apps Rust e2e driver binary (one driver for both apps: the strongest
   parity statement, a cross-repo input) or a gate-owned C XTest driver (needs the X11 sysroot members of P290 D1=A)?
7. **Judgement entries of the contract** — hierarchy/importance levels, toggle groups, layer input policies: derive
   them from the oracle (largest text per screen in the Rust tree; Rust's modal/non-modal layers) or have the owner
   declare them?
8. **P003 `sim` invariant D12** (event stamping) belongs to the P003 session.
9. **Which panel?** Physical size/diagonal (hence ppi) of the kiosk display and the mounting height / farthest viewing
   distance. Without them the mm thresholds (§3.10) and the visual-angle legibility floor cannot be enforced, only the
   scene-unit fallbacks.
10. **Target population for thresholds**: keypad ≥ 20 mm and other buttons ≥ 19 mm (older/low-dexterity-inclusive)
    or the younger-adult values? The standing-kiosk evidence is from young adults; older-adult evidence is seated or
    handheld (gap G7).
11. **Error dialogs: fixed 8 s or "until acknowledged"?** WCAG prefers no time limit for errors; ui-rules.md says 8 s.
    And which reading rate seals the dwell floor: 175 wpm or the inclusive 130 wpm?
12. **Who seals, and how?** The owner identity and signature mechanism for sealed files (§8.5), and the budget sizes
    (deviation cap, allowlist/no-op budget, skip/delete/tolerance budget).
13. **Rust lockstep**: invest in a headless Rust lockstep driver (club-apps work, T1xx.20, 5+ days) or keep L1/L2 on
    scenario replay + bundle only (cheaper; parity only on the 23 scenarios' steps)?
14. **Pseudo-locale scope**: at merge (doubles text-fit and render work for one language) or nightly only?
15. **Contrast metric**: seal WCAG 2 ratios (4.5:1 / 3:1) — APCA is unvalidated — and require "not colour-only" for

## 14. Measurement plan

1. **Cost**: T1xx.01 ms/state (render, ink, hit, LVGL dump, pseudo-locale); then per tier wall time on ten real merges
   (P003 §14 item 1).
2. **Yield**: distinct real UI defects per check per CPU-hour over the first month; a check that finds nothing and
   costs > [P] 5% of the nightly budget is demoted (P003 §14 item 3) — unless it is the only L4 check of a class.
3. **Noise**: FP rate per check during its report-first period; promotion only below [P] 1 FP per nightly.
4. **Escapes**: every UI defect found by a person after this lands is classified by which check should have caught it
   (P003 §14 item 4); a defect no check could catch opens a gate task.
5. **Determinism floor**: run-twice and cross-host renders of the full sweep; the expected pixel noise is 0 and any
   nonzero difference is filed as a determinism bug, never absorbed by a tolerance (closes gap G8 for our stack).
6. **Gate strength**: nightly self-mutation kill rate per property and key-validation kill rate; a property below
   100% on its own mutants is vacuous.
7. **Exploration saturation**: new abstract states per BFS depth and C8/C11 coverage over time; raise D when the last
   depth still adds states.
8. **Hardware**: input-to-photon latency and touch offset at release (T1xx.21), compared with the §3.10 bounds.

## 15. Literature slots LIT-1..LIT-8 (filled)

Each slot keeps the draft's question; the answer cites the corpus; residual gaps go to §17.

- **[LIT-1] Automated GUI exploration and state abstraction** (used in §4.3). Systematic event-based exploration with
  event-pair and invocation-termination coverage is the established adequacy model [E: Memon 2001; Strecker 2008;
  Belli 2001]; longer sequences find faults pairs miss, with event-triple coverage the strongest predictor in one small
  subject [E: Strecker 2008]. State abstraction decides everything and similarity thresholds fail (best universal
  threshold F1 0.24) [E: Yandrapally 2020; Baek 2016; Mesbah 2012 Crawljax]; dropping fields from the key hides bugs
  [E: Dong 2020; Amalfitano 2015]. Free resets favour BFS and its spanning tree is a compact regression suite
  [E: Choi 2017]; real-GUI pair coverage is very expensive [E: Nguyen 2014]; exhaustive search of a small exact model is
  instant [E: Rushby 2002]. Random exploration is a strong device baseline but a supplement here [E: Choudhary 2015;
  Su 2021 Themis; Groce 2012]. **Gaps**: pairwise/covering-array selection of GUI states and coverage-guided ordering —
  [E: none found — gap]; exhaustive exploration of Elm/Redux reducers (G1).
- **[LIT-2] Detection of layout/presentation failures** (used in §3.1–§3.3, §6.4). Relational geometry from the UI
  tree is the most precise family: X-PERT 18% → 76% precision, GWALI P 91% / R 100%, dVermin P/R 0.97, VFDetector
  ≈ 97–99% precision and 91% of its findings disjoint from a geometry checker, AccessiText geometry rules R 100%
  [E: Roy Choudhary 2013; Alameer 2016; Su 2022; Ryou 2018; Alshayban 2022]. FP sources are undeclared floating layers
  and intended clips/overlaps [E: Liu 2022; Walsh 2017]; minimum font size is a standard rule [E: Mahajan 2018];
  ±1 px relation tolerance is supported by off-by-one prevalence [E: Bielik 2018; Mahajan 2017]. **Gap**: no published
  precision/recall for clip detection from renderer font metrics (G4).
- **[LIT-3] Cross-platform/differential visual consistency** (supports D4; §3.6). Tree-based node matching with
  structural differences first: DiffDroid ≈ 86% precision, most FPs from text-bound padding [E: Fazzini 2017];
  oracle strength per event matters significantly [E: Memon 2003; Xie 2007]; normalisation is where precision comes
  from and the reference's bugs are inherited [E: McKeeman 1998; Barr 2015]. Image metrics across stacks are noisy:
  16% of 17,567 CI runs were FPs, a histogram metric 41.7% FP; different stacks render different pixels, identical
  stacks identical ones [E: Alégroth 2018; Donaldson 2017; Mowery 2012]; perceptual metrics are designed to forgive
  shifts [E: Ding 2020]. D4 is supported.
- **[LIT-4] Metamorphic testing for time handling** (used for `clock-origin-divergence`). **[E: none found — gap]** —
  no corpus source evaluates clock-origin or clock-shift relations for timer bugs. Indirect support only: exact
  metamorphic relations are precise (83.2%, 97%) while heuristic ones are not [E: Sun 2021; Su 2022]; time-varying
  state was an FP source for a rotation relation [E: Zaeem 2014]; virtual time and pinned epochs are tool practice
  only [E: Chromium 2026 (prac); LVGL 2026 (prac)]. The check stays [P]/[I]; its cost is 4 extra runs per walk.
- **[LIT-5] Minimum touch-target size** (provenance for `touch_min`; §3.10). Standing kiosk keypad plateau at 20 mm
  [E: Colle 2004]; older adults 16.5–19.05 mm [E: Jin 2007]; ≥ 14 mm for 97% accuracy [E: Leitao 2012]; error rate
  rises steeply below 15 mm in the wild [E: Henze 2011]; ~15 mm diameter captures 95% of touches [E: Holz 2010];
  handheld thumb 9.2–9.6 mm is a lower bound only [E: Parhi 2006; Park 2010]; spacing beyond ~1 mm does not change
  accuracy [E: Colle 2004; Sesto 2012; Leitao 2012]. Platform floors 44 pt / 48 dp and WCAG 24/44 px are policy
  without data [E: Apple Google 2025 (prac); Google 2025 (prac); W3C 2023 target size (std)]. Material 48 dp is kept
  as the scene-unit floor; the mm values need the panel ppi (§11 Q9). **Gap**: no standing-kiosk study with older or
  disabled users (G7).
- **[LIT-6] Transient UI elements / timing properties** (used in §3.5, §3.10). Minimum duration, bounded invariance,
  maximum duration and bounded recurrence are standard real-time patterns [E: Konrad 2005; Dwyer 1999]; bounded past
  MTL is monitorable [E: Ho 2014; Basin 2015]; unbounded liveness is not [E: Bauer 2011]; LTL acceptance testing found
  faults in 20 of 43 web implementations including transient-state problems [E: O'Connor 2022]; transient faults need
  per-event checks [E: Xie 2007]. The dwell floor rests on reading rates [E: Brysbaert 2019], WCAG timing (std) and
  platform defaults (prac). **Gap**: no empirical study of minimum display time for UI messages and no Bulgarian
  reading-rate data (G6).
- **[LIT-7] Golden-image/visual regression practice** (used in §6.4, §8.4, §8.5). Visual tests in CI: 0 FN but 16% FP
  executions [E: Alégroth 2018]; synchronisation and fuzzy-match instability dominate practice problems
  [E: Alégroth 2015]; baselines churn in 8.2% of commits, co-changed with code [E: Fujita 2023]; 13% of flaky fixes
  skip or delete [E: Thorve 2018]; timing and platform are the main flake causes [E: Romano 2021; Parry 2021]; LVGL's
  default self-blesses missing references [E: LVGL 2026 (prac)]; tolerances need a measured noise floor [E: Lu 2026];
  LLM triage can annotate, not approve [E: Kaynak 2025]. **Gaps**: no FP/FN measurement of exact goldens on a pinned
  software renderer (G8); no study of golden re-blessing by AI agents (G9).
- **[LIT-8] Text expansion EN → Bulgarian** (design margin for `text-overflow`). **[E: none found — gap]** for
  Bulgarian or Slavic languages (G3). Practitioner rules only: +40% overall, IBM table 2–3× for ≤ 10 characters down to
  1.3× above 70 [E: Practitioner 2022 (prac)]; a base-language-as-oracle layout check works for i18n failures
  [E: Alameer 2016]; 2× text scale exposes cropping [E: Alshayban 2022]; shrinking text to fit is an anti-pattern
  [E: Alameer 2019]. Design response: test with the real BG catalogue **and** a pseudo-locale exceeding it per message
  (§3.8), rather than a fixed margin. Our own data point: one BG subtitle needs 745 px in a 608 px box [M].
